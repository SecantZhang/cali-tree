# 260902-20:15:31 — Behavioral optimize–merge–optimize Cali-Tree

## Motivation

Implement the requested bottom-up Cali-Tree variant: first make specialized leaves correct,
then merge only leaves that actually transfer to one another, and retain only parents that do
not regress on held-out data. The live judge/optimizer should use GPT-4o.

## Changes

- `vejudge/core/calibration/calitree.py`: added `behavioral_complete_link` clustering. It
  probes optimized leaves on a common case set, builds normalized 3×3 behavior profiles, and
  ranks pairs with semantic complete-link similarity, profile similarity, and bidirectional
  balanced cross-generalization. Parent behavior is re-measured after every accepted merge.
- `vejudge/interface/node_calibration/calitree_nodes.py`: exposed the cluster algorithm and
  its three normalized weights in the train-node schema and dry-run call estimate.
- `run/run_imagenhub_calitree.py`: added behavioral-cluster CLI options and set `gpt-4o` as the
  default judge/optimizer model.
- `web/src/nodes/paramSchemas.ts`: exposed the new train-node controls in the UI.
- `tests/unit/calibration/test_calitree.py`: added a deterministic end-to-end hierarchy test
  showing the behavioral tree improves over the plain judge (0.00 → 1.00 accuracy) and records
  cross-generalization for the accepted merge.
- `docs/calitree.md`, `run/README.md`: documented the experiment and GPT-4o preflight command.

## Design decisions

- Prompt text is only one signal. Merge ranking uses behavior and transfer because similar
  wording cannot establish that two specialized decision rules safely compress.
- The existing held-out balanced-accuracy guard remains final merge authority; ranking never
  authorizes a merge by itself.
- Prior v2/delta results remain frozen baselines. No claim of a real ImagenHub improvement is
  made until the configured GPT-4o run completes against the plain judge.
