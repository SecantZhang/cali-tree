# 260722-13:00:30 — Add joint prompt and temperature calibration

## Motivation
The prior fitted tree was too shallow and the experiment could not distinguish whether a
judge's error depended on prompt family, sampling temperature, or a reusable semantic rule.
The goal was to improve held-out MAE without label leakage and to make any added tree depth
meaningful rather than forcing a complex tree onto a small sample.

## Changes
- Judge execution: recorded prompt/model/temperature provenance and included temperature in
  checkpoint identity so temperature sweeps cannot reuse stale scores.
- Adversarial calibration: added same-metric judge fan-in, debated the mean score once per
  video/metric, preserved both temperature variants and rationales, and versioned debate
  checkpoints against the anchor fingerprint.
- Joint semantic features: combined M3, M5, and M6 into one grouped task set with raw score
  mean/spread, prompt identity, prompt-scoped semantic questions, equal-video raw-rating
  weights, and video-grouped train/validation splits.
- Semantic tree: added bounded one-level split lookahead and training-only selection that
  requires a depth-2-or-greater prompt/rubric/rule branch plus at least 0.01 grouped-LOO MAE
  improvement before semantic capacity is selected.
- Evaluation: added prompt-bias and prompt-linear controls so prompt identity is not falsely
  credited to debate semantics; exposed per-prompt metrics and meaningful-tree diagnostics.
- Critic reliability: retry incomplete or malformed critic answers up to three times, record
  retry diagnostics, never cache an all-missing result, and repair old all-missing rows on
  Resume.
- Interface: display prompt tasks, judge variants, metric families, prompt-aware baselines,
  selected semantic splits, and the meaningful-tree decision.
- Workflow: added `joint_semantic_calibration_M3_M5_M6.json` for two temperatures across M3,
  M5, and M6 with a frozen joint semantic-tree evaluation.
- Tests: covered temperature cache invalidation/fan-in, joint features and grouping, prompt
  controls, lookahead interactions, meaningful selection, critic retries, API fan-in, and the
  joint mocked node path.

## Design decisions
Prompt family and temperature spread are deployment-available inputs. Debate-derived rules
remain eligible only when training-only grouped selection supports them; the threshold was
not lowered after viewing validation. A residual semantic-tree experiment was also evaluated
with training-only selection, performed worse, and was removed rather than retained as unused
complexity.

The approved live run at `logs/exps/260722-10:45:58-exps` used 33 independently labeled
videos (26 train, 7 validation), 99 prompt tasks, 779 raw-rating observations, and 197 judge
variants. The full linear semantic feature model achieved 0.97 held-out item-macro MAE versus
1.19 for global bias (improvement 0.22; 95% grouped-bootstrap CI [0.06, 0.38]). The selected
tree has depth 3 and uses temperature score spread, raw score, and prompt M6. Debate semantic
branches improved training grouped LOO by only 0.0067, below the fixed 0.01 threshold, and
were therefore rejected. This is reported as a data limitation rather than a semantic gain.

## Follow-ups
The seven-video validation split is sufficient to detect the overall calibration gain but is
too small and homogeneous to establish that debate-derived semantic rules generalize. A
larger, more diverse aligned-label set is still required before enabling those branches.
