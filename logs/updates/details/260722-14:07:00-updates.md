# 260722-14:07:00 — Add exploratory deeper semantic-tree selection

## Motivation
The semantic-first rerender intentionally selected one semantic decision per prompt subtree.
The user wanted to inspect a richer tree that fits more semantic distinctions while still
preventing raw-score branches and avoiding unconstrained depth.

## Changes
- `vejudge/core/calibration/debate/eval/semantic_selection.py`: added an opt-in deeper
  selection strategy. Among candidates within the existing 0.01 training-only grouped-LOO
  tolerance, it maximizes prompt coverage, distinct semantic questions, and semantic nodes
  before comparing error.
- `vejudge/interface/node_calibration/cl_semantic_tree_node.py` and
  `web/src/nodes/paramSchemas.ts`: added `prefer_deeper_semantic_tree`, defaulting to false.
- `web/src/panels/RightPanel/secondary/ClRuleTreeSecondaryTab.tsx`: added an explicit
  exploratory-depth warning and preserved the score-split/leaf-model explanation.
- `run/offline_rerender_semantic_tree.py`: added `--prefer-deeper`, records the overridden
  node parameter in derived graphs, and labels registered runs as semantic-deep.
- Tests: added selection coverage for the deeper-within-tolerance behavior and its UI warning.
- Registered ignored interface run `260722-14:04:20-semantic-deep` from the completed
  260722-10:45:58 checkpoints without gateway calls.

## Design decisions
The safer generalization-first strategy remains the default. Deeper preference is visibly
exploratory and cannot select a candidate outside the same 0.01 training-CV tolerance. Raw
score, score variance, and score range remain leaf-only inputs and can never form branches.
Distinct question count is ranked before total node count so repeatedly splitting one graded
question is less valuable than adding another semantic consideration.

## Verification
- Backend unit/integration: 469 passed.
- Frontend Vitest: 126 passed.
- Frontend production build: passed (existing bundle-size warning only).
- Playwright: 34 passed using the local mock gateway; no real gateway calls.
- The registered deep run has five semantic nodes, four distinct questions, depth-two prompt
  subtrees, all three prompt contexts, and zero raw-score splits. Training MAE improved from
  0.885 to 0.880 versus the shallow semantic-first tree; frozen-holdout semantic MAE changed
  from 1.008 to 1.017. Its training-CV penalty versus the lowest-error candidate is 0.009,
  inside the declared 0.01 exploratory tolerance.

## Follow-ups
The deeper tree fits training data slightly better but does not improve the seven-video
holdout. It should be used to inspect candidate semantic structure, not as evidence that
additional depth generalizes.
