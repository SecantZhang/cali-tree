# 260724-16:33:20 — Add recursive workflow folders

## Motivation

Workflows stored below `workflows/` in directories such as `workflows/examples/` were valid graph files but invisible in the interface because the backend only listed top-level JSON files.

## Changes

- `vejudge/interface/server/workflows_store.py`: recursively discovers workflow JSON, supports safe portable `folder/name` identifiers, creates parent directories on save, removes empty directories on delete, and rejects absolute, traversal, malformed, or escaped paths.
- `vejudge/interface/server/routes/workflows.py`: supports nested workflow paths for load, delete, and prior-run lookup while retaining the existing flat routes.
- `web/src/api/workflows.ts`: preserves folder separators while URL-encoding individual path components.
- `web/src/panels/LeftPanel/`: adds a recursive workflow-tree model and collapsible folder browser; the save field accepts `folder/name`.
- `web/src/App.css`: styles nested folder disclosure controls and hierarchy guides.
- `tests/` and `web/e2e/`: cover recursive CRUD, flat-name compatibility, unsafe paths, tree construction, and real-browser nested save/load/delete behavior.
- `README.md` and `vejudge/interface/interface.md`: document folder discovery, naming, storage, and safety constraints.

## Design decisions

The list API remains a sorted string array, with nested identifiers represented as slash-delimited paths, so flat-workflow clients remain compatible. The frontend derives the tree rather than coupling the backend to a presentation shape. Folder creation is implicit when saving `folder/name`; empty directories are cleaned after deletion. Each path component uses the existing workflow slug character set, preventing traversal without relying only on path normalization.
