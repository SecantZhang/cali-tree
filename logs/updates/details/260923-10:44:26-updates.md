# 260923-10:44:26 — Use official OpenAI and Gemini providers

## Motivation
The user no longer has access to the company LLM proxy and requested direct OpenAI
and Gemini support only.

## Changes
- Provider-scoped credential resolution from saved UI settings, environment variables,
  or project .env; official endpoints by default. Old unscoped credentials, proxy vars,
  and .env-raw are opt-in legacy configuration only.
- OpenAI Chat Completions token-limit handling and GPT-5.4-mini sampling compatibility;
  native Gemini GenerateContent serialization, image/video parts, response/usage mapping,
  and blocked-response errors. Shared wire formats for isolated GEPA workers.
- Provider routing across engines, AURORA, TextGrad/GEPA, graph judge/calibration nodes,
  benchmark modality clients, health checks, and concurrency probes. Tree embeddings use
  their own OpenAI credentials even with a Gemini judge.
- Independent provider keys in Settings, secret-free status responses, owner-only atomic
  credential-file writes, and a settings indicator covering either provider.
- .env.example, secret ignore rules, README and docs/providers.md setup/reference guide.
- Mocked regression tests and native Gemini support in the local browser-test server.

## Design decisions
Preserve prompts, experiment model IDs, checkpoints, and historical result artifacts.
Keep the old PlutoCreds import as a compatibility alias; no implicit legacy fallback.
Support OpenAI and Gemini only as requested; other provider engines were not extended.
Gemini uses native GenerateContent so existing video inputs have an official wire format.
Tree embeddings remain OpenAI-only; native Gemini embedding models fail explicitly.
Large Gemini uploads are not implemented: inline media above 19 MB encoded requires
shorter clips or sampled frames. Start a fresh run directory after changing providers
so old checkpoint predictions are not mistaken for new provider evaluations.
