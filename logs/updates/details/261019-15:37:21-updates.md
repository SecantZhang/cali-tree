# 261019-15:37:21 — Prioritize merge candidates with semantic profiles and compare fixed budgets

## Motivation
Implement semantic candidate ordering and test whether it reaches equal or better
compression with fewer parent fits while preserving local accuracy and coverage.

## Changes
- `critical/core/calibration/semantic_merge_v25.py`: versioned scheduler and pairwise coordinator using supported task distributions, overlapping-task prediction agreement, and shallow predicate families. Recomputes profiles after accepted merges; leaves frozen v24 code intact.
- `run/calitree_semantic_merge_v25.py`: standalone offline runner with ID/semantic ordering and independent fit budgets.
- `run/compare_calitree_semantic_merge_v25.py`: predeclared 4/8/24-budget paired comparison, separate logical accounting, physically memoized identical fits.
- `run/verify_calitree_semantic_merge_v25.py`: reconstructs pair ordering and candidate proposals, verifies budgets, invokes independent coverage/raw-input/retention audits, and compares the full control with historical v24.
- `tests/unit/calitree/test_semantic_merge_v25.py`: seven tests for semantic prioritization, ID/order invariance, local support, normalized profiles, validation and v24 parity.
- `docs/calitree_semantic_merge.md`, compact result/audit JSON and `run/README.md`: usage, results and limits.

## Design decisions
Ranking changes search scheduling only. It uses original local labels only to
identify correct support; development probes are not ranking inputs. Pairs remain
eligible, and all v24 parent and routing acceptance checks remain hard constraints.
The fixed ranking was not retuned after observed results. Memoization saves study
execution time without reducing the fit budget charged to any arm. Old sealed
code, inference defaults, prompts, and reserved final cases remain untouched.

## Verification
- 89 focused tests passed in 6.70 seconds (new semantic scheduler plus pairwise,
  coverage, rejection, cache, task coverage and local-compression suites).
- All six arms produce identical final gates: 10→9 experts, 59→56 terminal rules,
  1,290→1,256 stored conditions across three splits. Only split 2 merges.
- At per-split caps 4/8/24, both orderings use 10/18/30 total fits respectively.
  No semantic-order fit-count advantage. At cap 4, semantic scheduling reduces
  coverage rebuilds 5→3 and search states 506,188→499,951; at cap 8 states fall
  655,385→638,193. Full-budget work is identical.
- Both low-budget arms recover the old 30-fit result with 10 fits. This is a
  budget reduction shared by the control, not a semantic-ranking improvement.
- Every arm preserves 144/144 cached local predictions, 12 original child batches
  at 12/12, all 294 recorded coverage/final-label decisions and 112 exact regular
  fallbacks. Development accuracy stays 116/150.
- Independent audit passed: 24 schedules,
  116 logical fits, 30 physical unique fits,
  1764 recorded decisions. Full control exactly reproduces v24.
- Zero model calls and zero reserved final predictions. `git diff --check` passed.
- No interface/web files touched, so browser E2E is not applicable.

## Follow-ups
Semantic task similarity alone can rank a behaviorally incompatible pair first.
Keep this scheduler opt-in. A separate experiment could test joint task/behavior
scores or profiles over smaller supported rule regions. Results concern cached
local evidence and known regression cases, not fresh extraction stability.
