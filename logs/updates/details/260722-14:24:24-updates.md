# 260722-14:24:24 — Align calibration metrics and contain tree labels

## Motivation
The semantic-tree secondary tab displayed the training and held-out headings with different alignment from the right-aligned MAE values, and long structured semantic feature keys overflowed the fixed-width split boxes in the fitted decision-tree diagram.

## Changes
- `web/src/panels/RightPanel/secondary/ClRuleTreeSecondaryTab.tsx`: replaced presentation-only table cells with accessible column headers and assigned shared numeric-column classes and widths.
- `web/src/panels/RightPanel/secondary/ClRuleEvalSecondaryTab.tsx`: applied the same metric-table structure to the companion comparison view for consistent calibration reporting.
- `web/src/App.css`: added fixed, equal metric column widths plus common right alignment and tabular numerals for headings and values.
- `web/src/components/DecisionTreeView.tsx`: compacted structured semantic feature keys into a bounded concept label and prompt/question qualifier, and retained the complete feature or readable rule in a native SVG tooltip.
- Frontend tests: covered numeric-header structure, semantic key compaction, retained tooltips, and the non-overflowing visible label.

## Design decisions
Training and held-out columns use the same explicit width and right edge because their contents are numeric comparisons. Decision-tree labels are compacted semantically instead of shrinking all text: the visible box keeps the concept plus prompt/question identity, while hover exposes the complete value. Unknown and legacy feature formats receive a deterministic character-bounded fallback.
