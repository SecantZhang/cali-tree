# 260721-14:10:58 — Immediate hard stop for interface runs

## Motivation
The Stop button previously set a cooperative flag, so a node blocked in a synchronous model request or other long-running operation had to finish before the workflow became terminal. The requested behavior is a real immediate cancellation that stops local work, preserves completed checkpoints, and leaves the run resumable.

## Changes
- `vejudge/interface/server/run_registry.py` and new `run_worker.py`: moved each graph execution into a spawned worker process group, relayed progress and completed node results through IPC, atomically transferred normal final results, and added non-blocking process-group termination.
- `vejudge/interface/server/executor.py`: added a private completed-node callback so the parent retains outputs from nodes that finished before a later node is killed.
- Run finalization: Stop now transitions directly to terminal `stopped`, persists status/results before publishing terminal state, marks active/pending nodes stopped, releases resume claims after signalling the worker, and leaves flushed JSONL checkpoints intact.
- `web/src/panels/TopBar/RunControls.tsx`: removed the user-visible graceful `stopping` phase and consumes the terminal Stop response directly while retaining legacy wire-state tolerance.
- Interface documentation and tests: documented hard-stop semantics and remote-provider limitations; added process lifecycle, IPC, timing, checkpoint, failure-path, and real-browser stop/resume coverage.

## Design decisions
Python threads cannot safely interrupt a call blocked inside `requests.post`, so cancellation is enforced at an OS process boundary rather than with asynchronous thread exceptions. Each worker becomes its own POSIX process group; Stop sends SIGKILL to that group when safe, with a process-only fallback on other platforms or before group setup. The API does not join the killed worker, so process reaping and temporary-file cleanup happen asynchronously. Completed node outputs and append-only checkpoints are retained; the interrupted unit produces no checkpoint and reruns on Resume. Legacy `stopping` remains accepted by frontend types but is no longer emitted by this backend.
