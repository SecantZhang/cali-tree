# 260722-14:16:11 — Add topological auto-layout for workflow nodes

## Motivation
Large workflows could load or accumulate with nodes squeezed together, requiring extensive
manual dragging before their execution flow was readable.

## Changes
- `web/src/nodes/topologicalLayout.ts`: added a deterministic longest-path topological
  layout. Dependencies advance left-to-right, parallel nodes are stacked vertically using
  measured node dimensions, and spacing accounts for resized and collapsed nodes.
- `web/src/store/graphStore.ts`: added the `autoLayoutNodes` graph action, dirty-state
  tracking, and a per-tab layout revision used to trigger viewport fitting.
- `web/src/canvas/GraphCanvas.tsx`: automatically animates Fit View after a relayout.
- `web/src/panels/TopBar/TopBar.tsx`: added the `⇥ Layout` action, disabled for empty graphs.
- Groups retain their pre-layout member nodes and are repositioned/resized around those
  members. Invalid cyclic components are kept visible in a final column rather than stacked
  on roots.
- Added unit tests for dependency depth, parallel spacing, groups, cycles, store dirty state,
  and a Playwright workflow test covering real socket wiring, layout, non-overlap, and Fit View.

## Design decisions
Columns use longest dependency depth rather than the order nodes were created, so a node with
both a shortcut input and a longer dependency chain is placed after the full chain. Ordering
within one layer remains stable based on current vertical position and insertion order. The
operation changes only visual positions/group bounds, preserves node sizes and execution data,
and marks the workflow dirty so users can save the improved layout.

## Follow-ups
The current algorithm optimizes readable dependency layers and non-overlap, not minimum edge
crossings. A future optional crossing-reduction pass could improve extremely wide fan-out graphs.
