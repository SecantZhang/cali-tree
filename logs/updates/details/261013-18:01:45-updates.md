# 261013-18:01:45 — Single-call evidence judge and matched flat comparison

## Motivation

Implement the user's requested explicit evidence checks in one model call, derive
labels with a fixed policy, and benchmark against the same twelve flat-judge cases
using the same model and one presentation per case.

## Changes

- `critical/core/decision/single_call.py`: versioned structured evidence schema,
  validation, unknown-state bounds, pure deterministic label policy, and a
  single-call judge using existing DurableCalls and LMEngine transport.
- `critical/core/prompts/templates/single_call_evidence_v1/check.txt`: one-response
  observer prompt; target/source integrity and instruction-grounded material
  requirements, without overall labels or reference supervision.
- `run/calitree_single_call.py`: opt-in preflight/live/replay CLI; frozen source,
  prompt, policy, cases and baseline hashes; four workers, one durable HTTP attempt
  per case; paired metrics, token usage, evidence report and exact replay.
- `tests/unit/calitree/test_single_call_evidence.py`: semantic regression and
  mock-only end-to-end/replay tests.
- `docs/calitree_single_call_evidence.md`, `run/README.md`: usage and policy.
- `logs/exps/261013-single-call-evidence-balanced12-v1/`: complete frozen
  artifacts, estimate, ledgers, history, report, request audit and interpretation.

## Design decisions

Core/constraint evidence is evaluated jointly, not presented as independent
observations. No weighted averaging, voting, optimizer, learned thresholds,
per-case policy exceptions, extra editing models, reversed presentations, or
repeated judgments are introduced. Model-selected evidence and scope remain
fallible. Unknown states resolve only when all possible completions agree.

The saved flat judgments are reused, preserving their original eight correct
labels. Shared transport/settings and all image bytes are matched. The existing
fulfillment optimizer/default factory remain unchanged. This is a new explicitly
authorized comparison following the prior code rollback; archived optimizer
exploration is not resumed.

## Follow-ups

The result does not support an accuracy improvement from this decomposition on
the twelve diagnostic cases. The Yes/Partial mismatch remains; these previously
inspected cases and single draws do not establish generalization or repeat
robustness. Any further calibration requires a separate user-authorized study;
no optimizer goal is resumed.
