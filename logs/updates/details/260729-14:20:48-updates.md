# 260729-14:20:48 — Audit simple generalization and test core-completion rubric

## Motivation

The two-cutpoint calibrator improved EditInspector partial F1, but its remaining gap raised
two questions: whether a slightly richer score rule could approach 90% without the Cali-Tree
hierarchy, and whether an error-driven rubric could create a cleaner partial signal. Both
needed cross-dataset evidence rather than calibration-half accuracy alone.

## Changes

- `vejudge/core/prompts/templates/rubric_lite_v5/`: added a one-call experimental rubric
  with three fixed `0/50/100` core-completion scores and explicit tolerance for generation
  quality.
- `vejudge/core/calibration/artifacts/rubric_lite_v5_core_completion_experimental.json`:
  versioned the prompt, fixed thresholds, and non-deployment provenance.
- `vejudge/interface/node_calibration/calitree_nodes.py`: registered the v5 ordinal schema
  so deterministic score labels override inconsistent model-emitted labels.
- `vejudge/interface/node_calibration/rubric_lite_nodes.py` and frontend schemas: exposed v5
  as an explicitly experimental prompt/frozen model.
- `workflows/examples/rubric_lite_editinspector_core_completion.json`: added a blank-model,
  no-verifier workflow for reproducible v5 experiments.
- `docs/calitree.md`: documented the cross-dataset rule audit, small-sample threshold
  transfer, v5 negative result, costs, and the resulting deployment recommendation.
- Tests now cover loading the experimental artifact and parsing its fixed ordinal schema.

## Design decisions

A four-clause EditInspector rule was rejected despite 89.80% calibration-half accuracy and
42.86% partial F1. On the existing 600-case ImagenHub holdout it collapsed to 54.83%
accuracy and 8.70% partial F1. This is direct overfitting evidence, so it was not added to
the product.

V5 was designed as the smallest rubric-learning test: one global call, no tree, verifier,
embedding, editor feature, instruction lookup, or learned score pattern. It was not
promoted because its parser-corrected 80-case result was 72.50% accuracy and 10.53% partial
F1, below v4 plus development-fitted cutpoints at 80.00% and 44.44%.

The live run initially wrote 71.25% because the production parser did not yet recognize
the new rubric-version string and therefore trusted three inconsistent model labels. The
registered schema deterministically reparses the checkpointed raw `ordinal_scores`; the
corrected 72.50% report is stored alongside the run. No calls were repeated.
