# 260924-09:37:00 — Repeated-evaluation GEPA per-case repair pilot

## Motivation

Implement the approved ten-case prototype comparing single-draw GEPA repair with
five-draw feedback and independent ten-draw confirmation. Evaluate final reliability
using 30 fresh repetitions per case and arm, under a $15 estimated-cost cap.

## Changes

- Added `run/robust_prompt_repair_pilot.py`: frozen inputs, live gating, bounded calls,
  full request/response checkpoints, per-case optimization, final freeze, and reports.
- Extended `run/aurora_prompt_repair/gepa_worker.py` with opt-in JSON-lines RPC for
  independent repeated evaluations. Existing worker behavior remains the default.
- Added offline protocol, integration, reporting, checkpoint, and budget tests.
- Added `docs/experiments/robust_prompt_repair_pilot.md` with frozen protocol and reproduction.
- Installed GEPA 0.1.4 into an isolated Python 3.12 `.venv-gepa` environment.

## Design decisions

- Per-case error plus its single-case tail is redundant; use correctness directly.
- Official GEPA reflection/proposal machinery runs in the isolated worker. The parent
  owns model calls, budget accounting, sample identities, and fresh confirmation.
- One-step GEPA comparisons are restarted each round so incumbent evidence is fresh.
- Equal five-proposal budgets; call budgets are unequal and reported explicitly.
- Reject obvious instruction/identifier copying and missing JSON contract; these
  checks do not prove semantic validity or exclude subtle memorization.
- Final 900 draws are isolated from all optimization decisions and checkpoints.
