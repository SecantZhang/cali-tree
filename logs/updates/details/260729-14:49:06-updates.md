# 260729-14:49:06 — Stop stronger-judge A/B after failed partial gate

## Motivation

The preregistered A/B tested whether a stronger image model could improve partial while
retaining the simple one-call rubric and two-cutpoint calibrator. Its advancement rule
required a five-point partial-F1 gain and non-inferior ordinary and balanced accuracy.

## Changes

- `docs/experiments/rubric_lite_gpt41_editinspector_ab_result.json`: persisted exact model
  usage, five-fold metrics, fitted thresholds, confusion matrix, paired outcomes,
  stratified bootstrap intervals, and the failed advancement decision.
- `docs/calitree.md`: added the baseline/candidate comparison and documented why the
  candidate stopped.

## Design decisions

The live arm was not modified after preregistration. It used gpt-4.1, the v4 prompt,
temperature zero, two images in source/edited order, 512 maximum completion tokens, and
the exact 80 development cases. Five-fold seed-44 cutpoints were fitted with macro F1 and
the same class-recall constraint as the baseline.

Gpt-4.1 improved accuracy by 2.50 points and expected agreement with an individual rater by
2.08 points, but balanced accuracy fell 9.18 points and partial F1 fell 13.68 points. It
failed the partial and balanced gates. The protocol therefore stopped before the 312-case
confirmation partition; no post-hoc threshold or second model was tried.

## Verification

- Live execution completed with exactly 80 primary calls, zero cache hits, zero verifier,
  optimizer, or embedding calls, and 157,387 total tokens.
- Checkpoint and history logs each contain exactly 80 records.
- All five candidate folds independently selected `25.000001 / 50.000001`.
- Candidate metrics were recomputed from `graph_result.json` using the production
  `cross_validate_ordinal_thresholds` implementation.
- A 10,000-repeat seed-44 class-stratified paired bootstrap was recorded.
- Both experiment JSON files parse successfully.

## Follow-ups

- Do not advance gpt-4.1 on this rubric.
- Treat the remaining partial problem as rubric/target-definition learning rather than
  model scale or tree routing.
