# 261010-21:50:50 — Consolidate the fulfillment leaf optimizer

## Motivation

The user requested a single latest pipeline, shared components extracted from older generations, archived optimizers, exact saved execution/replay compatibility, offline verification and a commit.

## Changes

- Made fulfillment the fresh-run/default-demo behavior, added `run.calitree_fulfillment` and the unversioned public `create_leaf_optimizer` factory. Historical scoring modes remain explicit at the compatibility runner.
- Extracted shared flat program fields/provenance validation, independent execution/caching and single-slot transport recovery into `critical/core/decision/shared/`.
- Extracted local search, routing, confirmed selection, empirical metrics, evaluation, TextGrad backward loading/feedback, visual discovery, source pinning, reference conversion, failure replay and reports into `critical/core/optimization/program/shared/`. Shared feedback templates preserve the old prompt bytes exactly.
- Moved original structural, robust-tree/Pareto, typed-evidence, Boolean-counting, endpoint and whole-program comparison optimizers into `program/legacy/`, with stable module aliases at former paths. Archived the multimode runner behind its compatibility entry point.
- Replaced eager public imports with lazy exports. Importing the canonical optimizer or CLI loads no historical optimizer modules.
- Documented current usage, historical status, source pinning and replay; preserved all historical experiment artifacts and the existing prompt hierarchy/interface APIs.

## Design decisions

This is an organization/default change, not a scoring experiment. No artifact version was incremented. Preserve v2–v7 JSON formats and hashes, bindings, checker identities, template bytes, cache keys, logical slots, budgets, weights, thresholds and strict acceptance rules. Keep aliases instead of deleting compatibility code. Original pinned snapshots remain authoritative for historical resume; changed-source validation is not bypassed. New preflight pins extracted and archived code. The current paired runner retains binary as its explicit control under the common graded observer. No model calls, commits to historical results, pushes, UI changes or new model families.
