# 260722-13:44:00 — Make semantic evidence define tree decisions

## Motivation
The completed 260722-10:45:58 joint calibration run selected a tree dominated by
`score_std` and `base_score`; only one branch used prompt context and no mined semantic
question was selected. This made the object called a semantic tree difficult to interpret
semantically. The redesign follows Chanmee and Kesorn's ontology-guided Semantic Decision
Tree principle (Advanced Engineering Informatics 58, 2023, 102156): domain importance
adjusts empirical split gain so learned decisions resemble domain logic.

## Changes
- `vejudge/core/calibration/semantic_tree.py`: added score-aware ridge leaf models and a
  fixed prompt router whose learned subtrees can split only on ontology-backed rubric or
  debate evidence; added auditable semantic/raw-score split counts.
- `vejudge/core/calibration/debate/eval/semantic_selection.py`: replaced mixed score/rule
  feature-set selection with semantic-only candidate selection. Training-only grouped LOO
  still controls capacity, while configurations within 0.01 MAE of the best candidate are
  ranked by prompt-level semantic coverage and simplicity.
- `vejudge/interface/node_calibration/cl_semantic_tree_node.py`: wired prompt-routed
  semantic model trees, confined `base_score`, `score_std`, and `score_range` to leaves,
  and recorded the architecture, selection trade-off, semantic coverage, and warnings.
- `web/src/components/DecisionTreeView.tsx` and
  `web/src/panels/RightPanel/secondary/ClRuleTreeSecondaryTab.tsx`: distinguish fixed
  context routing, learned semantic decisions, and dynamic model leaves in the detail UI.
- `run/offline_rerender_semantic_tree.py`: added a no-call checkpoint rerender utility that
  fails if any LLM request would be needed and writes a separate comparison artifact.
- Tests: covered prompt routing, score-split exclusion, leaf controls, semantic coverage
  selection, backend node reporting, and frontend diagnostics.

## Design decisions
Raw judge scores remain valuable calibration signals, so they were not discarded. They are
used only inside regularized leaf models and cannot create branches. Prompt identity is a
fixed router rather than a learned semantic finding. Each prompt therefore gets a local
semantic subtree and questions that do not apply to a prompt cannot act as zero-valued
prompt proxies. The selection tolerance is deliberately small and training-only: it chose
three ontology/rubric decisions covering M3, M5, and M6 for a 0.003 grouped-LOO penalty over
the single-rule candidate, without consulting validation labels.

## Follow-ups
The semantic structure is now genuine and more accurate than the previous semantic tree,
but it does not beat the unrestricted linear model on seven validation videos. A larger and
more diverse labeled validation set is still needed before claiming semantic generalization.
