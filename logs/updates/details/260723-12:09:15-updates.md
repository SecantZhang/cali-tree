# 260723-12:09:15 — Stream adversarial debates live and preserve completed content

## Motivation
Adversarial chat histories appeared only after a complete item finished, and their live partial content disappeared as soon as the calibration node became done while a downstream node continued running.

## Changes
- Debate execution now publishes a cumulative display-safe transcript when a conversation starts and immediately after every complete human-proxy or judge response. Progress callback failures cannot affect calibration, and cached debates are not replayed as fake live activity.
- The frontend run store tracks revisioned per-node/per-item live debates, marks completed items, and atomically promotes authoritative terminal results while retaining partial content for interrupted nodes.
- The Adversarial Calibration secondary tab merges active chats with completed partial results, preserves manual selection across concurrent updates, shows the next responding role, and follows new messages only while the viewer remains near the chat bottom.
- Final batch remainders are flushed so `batch_size > 1` cannot hide completed items until workflow termination.
- The browser mock and adversarial Playwright flow now create a reliable downstream-running window and verify that live turns arrive before calibration completes and remain visible afterward.

## Design decisions
Live granularity is one complete model turn rather than token streaming because the current engine contract returns complete structured responses. Websocket payloads are cumulative and revisioned to avoid duplicate bubbles and recover prior turns when a later event arrives. Persisted transcripts remain authoritative; live state is presentation-only.
