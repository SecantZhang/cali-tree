# 260729-16:01:41 — Add explicit human-review decisions

## Motivation

CaliTree already measured selective accuracy internally, but downstream consumers still
received only `yes`, `no`, or `partial`. Ambiguous predictions needed an explicit,
machine-readable `needs_human` outcome without turning abstention into a fourth calibration
target or inflating the model's accuracy.

## Changes

- `vejudge/interface/node_calibration/calitree_nodes.py`: added the optional
  `human_review_mode=selective_policy` contract, target-blind persisted-policy application
  for cached and new predictions, explicit decision metadata, fail-fast validation before
  model calls, and expanded selective-system metrics.
- `web/src/nodes/paramSchemas.ts`: exposed the review-mode selector on Cali-Tree Judge.
- `web/src/panels/RightPanel/secondary/CaliTreeWorkbench.tsx`: separated full-coverage
  accuracy from auto-decision accuracy and displayed review volume, error capture, partial
  review rate, and per-case deployment decisions.
- `web/src/panels/RightPanel/secondary/CaliTreeEvalSecondaryTab.tsx`: added a dedicated
  Cali-Tree Eval dashboard for full-coverage and human-review operating points.
- `workflows/examples/rubric_lite_editinspector_zero_shot.json`: enabled the persisted
  selective policy while leaving the billable model field intentionally unset.
- `docs/calitree.md`: documented the output contract, safeguards, formulas, and the
  evidence-backed ImagenHub and EditInspector operating points.
- Backend and frontend tests: covered explicit review routing, no-policy fail-fast behavior,
  decision metrics, workbench rendering, and the new evaluation dashboard.

## Design decisions

`needs_human` is a deployment decision, not a human target label. The original
three-class `label` is preserved for full-coverage confusion matrices and accuracy;
`decision_label` becomes `needs_human` only when the frozen selective policy rejects a
case. This makes coverage and auto-decision accuracy auditable and prevents reviewed cases
from being counted as model successes. The perfect-human-review metric is labeled as a
system ceiling rather than accuracy. Review mode requires a persisted policy and errors
before engine creation when one is absent.
