# 261019-12:42:21 — Reject reviewed transfer errors without losing local or correct transfer routes

## Motivation

The user asked to inspect the 22 wrongly accepted transfer cases and improve the
coverage gate to reject them while preserving local trained accuracy. The reviewed
outcomes are now explicitly development/calibration data.

## Changes

- Added `counterexample_coverage_v23.py`: bounded, monotone rejection calibration
  using OR clauses of at most three declared Boolean evidence/task literals.
- Protects every original local example and every previously correct accepted
  transfer example. Existing rejections remain rejected; allowed expert verdicts
  are unchanged. Identical observable inputs cannot be separated by source IDs.
- Added offline fitting/replay runner, complete 22-case evidence review, error-only
  leave-one-out diagnostic, and independent audit of all protected/rejected routes.
- Added eight meaningful rejection tests and replayed the prior 62 tests.
- Exported three calibrated gates, compact results, explicit completion evidence,
  inference usage and measured limitations.

## Design decisions

The 22 error slots are 17 distinct examples: fourteen Partial references, seven No,
and one Yes. Missing physical-state support and feature interactions were not fully
captured by the earlier coarse semantic envelope. All errors are separable from the
protected correct pool using the existing vocabulary; no new case-specific feature,
image hash, instruction lookup or changed tree verdict was needed.

The fitted layer uses 21 clauses and 35 literal tests across the three gates.
The limits are three literals, 20,000 search states per error, 64 clauses and 256
calibration examples. All 38 correct transfer acceptances are protected to avoid a
reject-everything solution. The runtime contains no reviewed-case list or reference
labels. Fallback uses the exact regular prompt/response contract unchanged.

## Follow-ups

The requested regression objective is achieved. Broad unseen-error rejection remains
unproven: holding out each reviewed error while retaining the protected pool rejects
only 1/22. The post-fit 38/38 accepted-prediction precision is a calibration result,
not fresh validation. Keep this path opt-in and use genuinely new cases for a future
independent assessment rather than describing these reviewed failures as held out.
