# 261026-14:01:09 — Merge equivalent semantic factors in boosted trees

## Motivation

The user asked whether boosted trees could be semantically merged to reduce
complexity after a standalone single-tree replacement lost accuracy. Test a
function-preserving alternative before broadening any semantic conditions.

## Changes

- `critical/core/calibration/boosted_factor_merge_v175.py`: canonical Boolean
  leaf alignment, grouping by identical named semantic predicates, compensated
  score summation, exact-zero sparse tables and a source-forest-free scorer.
- `run/calitree_boosted_factor_merge_v176.py`: six compiled backbones, independent
  exhaustive factor verification, native/scalar comparison, V112/V144 context
  and routing replay, actual high-level cached judge substitution audit.
- `tests/unit/calitree/test_boosted_factor_merge_v175.py`: reordered predicates,
  exact cancellation, constant trees, distinct predicate semantics, portable
  serialization and integrity/input checks.
- Documentation and machine summary of complexity, preserved behavior,
  floating-point limits and selected-loader status.

## Design decisions

Merge only identical semantic predicate sets, never equal fitting columns or
similar labels. Keep every score contribution and source membership. The full
backbone compresses1200→513 factors,9574→4095 condition occurrences,915168→89550
score scalars. Canonical scoring bytes5672915→2275487 (59.9% reduction).

This shares named semantic structure without abstracting a broader rubric.
It is exact in real arithmetic; changed floating summation order is explicitly
tested rather than claimed bitwise identical. The executable compact scorer
retains no original forest. High-level verification substitutes only scoring
within the original frozen parent stack. Default serving selection/loader
and all existing artifact identities remain unchanged.
