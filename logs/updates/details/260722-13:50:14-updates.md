# 260722-13:50:14 — Register offline semantic rerenders as interface runs

## Motivation
The semantic-first checkpoint rerender was stored as a supplemental JSON file inside the
source experiment directory. The VEJudge Runs column discovers standalone interface run
directories, so the rerender could not be opened from the UI.

## Changes
- `run/offline_rerender_semantic_tree.py`: added `--register-interface-run`, which creates
  a separate derived `interface_graph` run containing the source graph and node results,
  replaces the semantic-tree and Rule Comparison outputs, records source provenance, and
  explicitly disables live calls.
- Created the ignored derived run `260722-13:49:56-semantic-first`, labeled
  `joint_semantic_calibration_M3_M5_M6 [semantic-first rerender]` in the Runs column.

## Design decisions
The source run remains immutable. The derived run has its own ID, status, result snapshot,
and workflow metadata, and carries `derived_from_run=260722-10:45:58`. It does not copy the
source checkpoint or LLM history because it is a completed inspection artifact rather than
a new gateway execution. The utility still installs a no-call engine and fails if any
missing checkpoint would require an LLM request.

## Verification
- Executed the registration path successfully with no LLM calls.
- `list_disk_runs()` returns `260722-13:49:56-semantic-first` first with status `done`, 23
  nodes, and the semantic-first workflow label.
- Verified the stored outputs contain three semantic splits, zero raw-score splits, semantic
  held-out MAE 1.008, and the refreshed Rule Comparison report.

## Follow-ups
The Runs panel query is not live-polled; an already-open panel may need to be reopened or the
page refreshed once to display a newly created offline run.
