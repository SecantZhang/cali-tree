# 260729-15:40:21 — Stop the v6 evidence ledger after stage 1

## Motivation

The v4 score-collision audit showed that downstream calibration cannot reconstruct partial
evidence that the aggregate scores discard. V6 tested the smallest representation-level
change: one semantic-completion score supported by a compact condition ledger, while
retaining one judge call and two global cutpoints.

## Design decisions

V6 lists at most four conditions with absent/emerging/mostly/complete status, achieved and
missing evidence, one semantic residual type, and one continuous completion score. It adds
no model pass, tree, router, embedding, optimizer, classifier, dataset feature, or editor
feature.

The no-call dry run estimated exactly 80 calls. The first live launch made zero calls
because the worktree did not resolve the main repository credential file; it is retained
as a failed run. The corrected launch explicitly pointed credential resolution at the
existing repository file without logging secrets.

All 80 schemas were valid, but the model emitted completion 100 for 55 cases and residual
type `none` for the same count. Five-fold task-grouped OOF accuracy was 71.25%, balanced
accuracy 54.01%, and partial F1 10.00%, versus 80.00%, 68.65%, and 44.44% for v4. Only the
schema gate passed. The protocol therefore forbids final or cross-dataset v6 calls. The
runtime default remains v4 plus two cutpoints; v6 is a reproducible negative control.
