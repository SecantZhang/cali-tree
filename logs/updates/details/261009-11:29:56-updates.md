# 261009-11:29:56 — Disable semantic audit and use flat counting

## Motivation

The user explicitly selected independent required conditions with all/some/none counting, removing semantic auditing and
the model-based final adjudicator. Existing progress helpers and conditional branches cannot be counted under that rule.

## Changes

- Added `decision-leaf-v5` / `typed-counting-v1` flat programs, label-free compilation and deterministic counting.
- Added independent visual check execution, distinct unknown/failure handling, cache identity and exact saved-leaf dispatch.
- Added atomic add/remove/revise/split edits with immutable original provenance and requirement coverage.
- Added a counting optimizer that retains Luna-first/Sol escalation and empirical gates with no audit calls or fake approval.
- New CLI runs default to counting; semantic mode remains explicit and saved runs retain their recorded format.
- Added production pixel-grounded offline demonstration, focused tests and updated design/usage documentation.

## Design decisions

Every vote is a required condition; pass means satisfied. All pass → yes; all fail → no; known mixture → partial. Any
unknown or failed observation leaves the result unresolved. All checks run independently. There is no extra final model
call and no semantic review. Confidence/stability gates remain for empirical robust status. Historical artifacts are never
reinterpreted as counting. No new paid experiment, commit or push is included in this change.

## Verification

Focused counting/v4 suites: **69 passed** before two additional failure-propagation cases. Final full offline unit suite:
**1,352 passed, 23 skipped**, including 42 counting tests. Production offline demo returned all-pass yes, mixed partial,
all-fail no, with zero model calls. Free twelve-case preflight confirmed the default counting manifest. The historical v4
experiment replayed from pinned sources without model calls or changed results/accounting. Tests verify absence of
auditor/readout requests, label isolation, counting combinations, immutability, coverage, failure propagation,
cache freshness, exact reload and zero-call replay.

## Follow-ups

A separately frozen live counting comparison can measure the new scoring rule. Previous v4 scores are not evidence of v5
accuracy. Semantics are intentionally not certified by a reviewer; parent learning, conditional trees and UI remain deferred.
