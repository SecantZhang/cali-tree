**Reporting period:** July 15–22, 2026

**Format:** Slide draft for mentor discussion

## Slide 1 — Project purpose

My project is to build a complete system for calibrating multimodal LLM/VLM judges that evaluate AI-generated video edits. The system combines video and annotation loading, judge execution, adversarial negotiation between a judge and a human-proxy critic, semantic prompt distillation, ontology-guided decision-tree calibration, statistically honest evaluation, run management, and an interactive workflow interface. The goal is not only to reduce score error, but also to produce calibration decisions that are interpretable, reusable, leakage-safe, and grounded in observable editing evidence.

**Main progress this week:** The project moved from a small rule-tree prototype into a more complete and reliable calibration system with raw human ratings, multi-model data, semantic-first trees, frozen held-out evaluation, resumable execution, and substantially improved workflow inspection.

## Slide 4 — Calibration system architecture

- Split calibration nodes into two explicit roles:
  - **Agent Calibration:** produces debate histories, semantic summaries, and corpus-level calibration guidance.
  - **Model Calibration:** fits rule trees and semantic trees from completed calibration evidence.
- Added shared node templates so every node in a role inherits the same input/output contract.
- Connected corpus-level calibration prompts back into downstream Judge nodes.
- Added a standalone Rule Comparison node that reports base, bias, linear, tree, and semantic comparators.
- Replaced raw text tree dumps with interactive SVG decision trees showing splits, branches, leaves, sample counts, and rule tooltips.
- Added an Alignment Report node that frames judge SRCC/PLCC/KRCC and MAE against human agreement and published VE-Bench baselines.

**Why this matters:** Calibration is now a modular system of producers, fitters, evaluators, and reusable artifacts rather than one monolithic pipeline stage.

## Slide 5 — Semantic prompt distillation and leakage control

- Removed item-specific target scores, correction magnitudes, and reasoning traces from optimized prompts.
- Added a shared semantic-summary schema:
  - principle
  - applies when
  - evidence to check
  - scoring guidance
  - optional counter-consideration
- Added two modes:
  - **Rule-based:** deterministic, offline, and free of extra model calls.
  - **LLM-based:** one dedicated summarizer call per item using a user-selected engine.
- Both modes use the same leakage validator, deduplicator, structured renderer, and 250-word cap.
- LLM errors or unsafe summaries visibly fall back to the rule-based result instead of losing the completed debate.
- Debate and summarization checkpoints are separate, so changing summary mode does not repeat expensive negotiation.

**Offline validation:** Rule-mode rerendering produced non-empty prompts for all 10 checked items, with **0 leakage failures** and prompt lengths of **117–176 words**.

## Slide 6 — Stable adversarial negotiation

- Replaced changing per-round annotator targets with one immutable disagreement profile per video.
- The profile contains rating count, histogram, range, median, modes, polarization, and lower/higher considerations.
- Required the human-proxy critic to address both sides of disagreement rather than choosing a convenient annotator.
- Capped debates at six rounds.
- Added early stopping after two rounds without a new normalized semantic finding.
- Detects repeated score cycles, including A–B–A–B and longer cycles.
- An oscillating unresolved debate now keeps the original score instead of accepting an arbitrary final turn.
- Added video-grounded independent-critic extraction, retry logic for incomplete structured answers, and protection against caching all-missing responses.
- Fixed malformed LLM JSON so one bad critic response degrades gracefully rather than crashing the entire calibration run.

**Outcome:** Negotiation is now used to extract reusable semantic evidence, while unresolved numerical disagreement is explicitly recorded instead of hidden.

## Slide 7 — Statistically honest calibration and evaluation

- Raw ratings remain separate observations, but each receives weight `1 / ratings_for_item`, so every video contributes one total unit.
- Linear, CART, semantic-tree, bias, and metric calculations now support sample weights and item groups.
- Reports distinguish **independent videos** from **raw rating observations**.
- Item-macro MAE is the primary error metric.
- New nodes default to a deterministic **frozen holdout** split; legacy workflows retain clearly labeled exploratory grouped leave-one-out behavior.
- Rules are mined only from validated training summaries.
- Held-out labels and label-grounded transcripts never enter deployment-time features.
- Constant semantic questions are removed and reported with prevalence and reason.
- Reports warn about constant base scores, missing aligned labels, fewer than 20 training videos, or fewer than 5 validation videos.
- A positive claim requires at least five validation videos, MAE improvement of at least 0.05, and a grouped-bootstrap 95% confidence interval excluding zero.

**Key correction:** The system now separates gain from global bias, gain from score-only calibration, and the incremental contribution of semantic rules. It no longer credits semantic rules for improvements actually caused by fitting the raw-score slope.

## Slide 8 — Semantic decision-tree evolution

1. **Initial rule tree:** An independent critic produced useful rule features; on 13 M5 videos, held-out MAE improved from **0.50 bias to 0.41 tree**.
2. **Ontology-weighted tree:** Semantic concepts from the editing-error ontology guided split importance; held-out MAE was **0.315 vs 0.336 for plain CART** on the same small set.
3. **Guarded graded tree:** Added signed evidence strength, weighted absolute-error splits, robust median leaves, and training-only capacity selection. This prevented an all-rule model from overfitting.
4. **Joint prompt-aware tree:** Combined M3/M5/M6, prompt family, two temperatures, raw-score spread, and semantic questions while keeping video-grouped evaluation.
5. **Semantic-first redesign:** Prompt identity became a fixed router; raw score and score variability moved into regularized leaf models; learned branches can split only on ontology-backed rubric or debate evidence.
6. **Exploratory deeper mode:** Added an opt-in strategy that prefers more distinct semantic questions within the same 0.01 training-CV tolerance. The default remains the safer generalization-first selection.

**Current structure:** The semantic-first rerender selected **3 semantic splits, 0 raw-score splits**, covering M3, M5, and M6. The exploratory deep rerender contains **5 semantic nodes and 4 distinct questions**, again with 0 raw-score branches.

## Slide 9 — Main experimental results

| Experiment | Data | Held-out result | Interpretation |
|---|---:|---:|---|
| Early independent rule tree | 13 videos | Tree 0.41 MAE vs bias 0.50 | Directional evidence that independent semantic checks help |
| Early ontology semantic tree | 13 videos | Semantic 0.315 vs CART 0.336 | Ontology weighting improved small-sample generalization |
| Corrected score-only calibration | 33 videos; 26 train / 7 validation; 410 ratings | 1.114 vs bias 1.176; gain 0.062; CI [0.004, 0.150] | Statistically supported gain over global bias |
| Incremental rule signal | Same split | 1.107 vs score-only 1.114; gain 0.006; CI [-0.031, 0.042] | Semantic-rule increment was indistinguishable from score-only calibration |
| Guarded graded semantic tree | Same split | 1.062 vs bias 1.176; gain 0.114; CI [0.003, 0.206] | Guarded semantic model beat global bias; semantic increment remained uncertain |
| Joint M3/M5/M6 linear semantic model | 33 videos; 99 prompt tasks; 779 ratings; 197 judge variants | 0.97 vs bias 1.19; gain 0.22; CI [0.06, 0.38] | Strong overall joint calibration gain |
| Semantic-first tree | 7-video validation | 1.008 vs prior semantic tree 1.066; unrestricted linear 0.974 | More genuinely semantic and better than prior tree, but not best overall predictor |
| Exploratory deeper semantic tree | 7-video validation | 1.017 vs shallow semantic-first 1.008 | Better training fit, but no held-out benefit from extra depth |

**Most important conclusion:** The system now demonstrates meaningful overall calibration improvement, but the current validation set does not yet prove that debate-derived semantic rules add performance beyond score-only or unrestricted linear calibration.

## Slide 10 — Reliability and run management

- Moved every graph run into a dedicated spawned worker process.
- Stop now hard-terminates the local worker and descendants immediately instead of waiting for the current model call.
- Completed checkpoints survive; the interrupted item is absent and reruns on Resume.
- Resume attempts receive unique public run IDs while reusing prior checkpoint directories, fixing same-second Stop/Resume websocket hangs.
- Added disk-backed run reconstruction and a Runs browser for opening or resuming past executions after server restart.
- Added a no-call rerender path that reuses completed checkpoints and registers derived semantic-tree runs in the interface.
- Restored the sanitized credential parser fixture so the full backend suite can run cleanly.
- Fixed literal JSON braces in custom judge prompts, which previously caused Python format-specifier crashes.

**Limitation:** Hard stop closes the local request immediately, but cannot guarantee cancellation or refund of work already accepted by a remote provider.

## Slide 12 — Current status and next steps

### Current status

- The end-to-end calibration system is functional across data loading, judging, negotiation, semantic distillation, model fitting, held-out evaluation, visualization, checkpointing, and resume.
- Overall calibration gains are now measured with leakage-safe and uncertainty-aware evaluation.
- Semantic-tree branches now represent actual rubric/ontology evidence rather than raw-score thresholds.
- Deeper semantic structure is available for exploration, but is not presented as a generalization improvement.

### Main limitations

- Only **7 validation videos** are available in the current frozen split.
- The labeled pool is still too small and homogeneous to establish semantic-rule generalization confidently.
- Debate-derived semantic features have not yet shown a statistically significant gain over score-only calibration.
- One labeled Grapenut item has no rendered video.

### Next steps

1. Expand and diversify independently labeled training and validation videos.
2. Improve negotiation distillation so questions capture distinct, observable editing decisions rather than paraphrases.
3. Analyze critic feature prevalence and missingness before increasing tree depth further.
4. Compare the frozen semantic-first model against stronger score-only and state-of-the-art video-evaluation baselines.
5. Keep the deep semantic tree as an interpretability tool until held-out evidence supports its deployment.
